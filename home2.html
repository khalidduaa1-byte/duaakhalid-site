01 / Field data system

Beauty Advisor Sales Tracker

Dolce & Gabbana Beauty · travel retail MEA

A PWA where 18 beauty advisors log daily sales, behind an ingest pipeline that de-duplicates the supervisor export before any KPI is calculated.

The mess

Advisor performance arrived as a supervisor's Daxium Excel export whose layout changed month to month, with duplicate rows on the same advisor, date, store and shift. Duplicates double count sales and inflate Days Worked, so no daily KPI could be trusted and productivity could not be compared across cities until month end totals arrived weeks late.

What I did

Framed the problem, defined the dedup key, built the ingest pipeline and the app, and ran the rollout across 3 markets.

Outcome

1,324 rows ingested, 0 rejected, 29 duplicates removed and 396 attendance rows in one full run across January to April. Live with 18 advisors in Cairo, Sharm and Hurghada, and presented to global beauty leadership in June 2026.

02 / Personal build

Move-Out Sale Site & Tracker

Personal build · Dubai

One Python script generates the buyer facing catalog and the internal profit tracker from a single item list, so the listing and the accounting cannot disagree.

The mess

Selling 31 pieces of furniture meant re-answering the same questions item by item over WhatsApp, and pricing everything off store catalog pages that turned out to be wrong by more than double. One dresser was recorded at AED 1,100 when it had actually cost 499, which put a phantom discount badge on a live page.

What I did

Wrote the generator, set the pricing rules and ran the sale end to end. The generator prices against purchase price, so a saving cannot be displayed unless it is real.

Outcome

20 of 31 items sold in 30 days. AED 8,400 recovered against AED 10,688 paid for those items, a 78.6% recovery rate. AED 4,900 still on the table across 11 items. Site launched 29 June 2026.

Python · Excel modelling · static site · pricing rules

Live catalog → Repository →

The sheet says 21 of 32. A COUNTIF counts rows, not objects. One row is a synthetic Dining Set Bundle whose table and chairs are also listed individually. The honest figure is 20 of 31.

What 78.6% measures. Recovery against what was paid for the items sold, not against total apartment spend. One cost is deliberately unallocated: curtains, AED 2,100 across two rooms, with a written note that real recovery is worse than the tracker shows until it is resolved.

Where the dates come from. Git history, which records when an item was marked sold rather than when money changed hands. The Excel has a Sold Date column the script never writes, so per item days to sell is not in the tracker.

A live defect I have not fixed. The site renders 0 items available from a hardcoded placeholder that the JS overwrites on a normal load. It should read 11. Not sold out.

03 / Hackathon build

Homebase

Co-founded · two person team

A fixed format context block that a voice agent uses to dispatch maintenance vendors. Dispatching by phone means a human assembling the same context every time: what is broken, which unit, when the tenant is free, and what else that vendor already has booked. Assembled ad hoc, it comes out differently on every call and details get dropped.

The system prompt stays static and per call variation is injected as a context block with fixed fields. The default path is a deterministic template builder. The model path only runs with USE_LLM_SCOPE=true, because a string template was sufficient for the job.
